# VSPi 1.3.0

VSPi 1.3.0 让默认 VSPLab Provider 覆盖主流国产模型，修复 /reload 在部分终端下会话中断的问题，并让 plan_create 创建的 Plan 立即可见。

## VSPLab 复合模型目录

内置 VSPLab Provider（VSP Open 中转站，`https://api.vsplab.cn/v1`）从 5 个 GPT 模型扩展为 33 个模型的复合目录：

- GLM（智谱）×9、Kimi（月之暗面）×5、DeepSeek ×4、GPT（OpenAI）×9、Claude（Anthropic）×7。
- 按模型家族选择协议：GPT / DeepSeek / GLM 走 `openai-responses`；Kimi 走 `openai-completions`；Claude 走 `anthropic-messages`（baseUrl 去掉 `/v1`，由 SDK 自行拼接 `/v1/messages`）。
- 共享元数据按模型从对应上游 Pi catalog 继承（contextWindow、成本、effort 档位、输入能力）；无上游条目的模型保持运行时默认，不手抄规格。
- `/model` 模型选择器的 curated 规则按品牌家族匹配 VSPLab 下的模型；Kimi K3 官方人民币牌价按 id 前缀命中。
- 自定义 Provider overlay 新增 per-model `inheritFrom`，可与 `api` / `baseUrl` 一起按模型覆盖。

## /reload 稳定性

- 采纳李超凡的修复（原 MR !1）：reload 启动器不再 `unref()` 续接进程，老进程作为 shell 的前台 job 驻留到续接进程退出。此前老进程退出后 shell 会收回 TTY（部分环境还会注入 shell hook 字符串），与仍在读 TTY 的续接进程冲突，表现为 EIO 和会话中断。
- spawn 逻辑提取为 `spawnReloadChild` 模块并补单测与真实 PTY 回归测试。
- parent-death watchdog 保持启用：老进程意外崩溃时它会在宽限期后收掉孤儿化的续接进程并把终端还给 shell，这是预期的自愈路径。

## Plan 可见性

- `plan_create` 现在创建即绑定当前会话；`/plan` 面板立即可见。此前 Plan 只写入工作区存储、从不绑定，除非模型恰好补调 `plan_bind`，否则面板永远为空（已有未绑定的 Plan 可让模型调一次 `plan_bind` 找回）。
- 绑定失败不丢创建结果：失败原因会返回给模型并提示用 `plan_bind` 手动绑定。
