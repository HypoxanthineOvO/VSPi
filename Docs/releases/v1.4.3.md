# VSPi 1.4.3

VSPi 1.4.3 修复 VSPLab Kimi K3 在完整 TUI coding-agent prompt 下被上游拒绝的问题，并收敛遗留的 VSPLab Open 重复配置。

## Kimi K3 Provider 兼容

- VSPLab 的 `k3`、`k3-256k`、Kimi For Coding 与 Kimi K2.7 Chat Completions 模型显式声明不支持 `developer` role。
- Provider request 边界会把 VSPLab Kimi payload 中的 `developer` instruction 降级为 Kimi 支持的 `system` role；覆盖新会话、resume、import、prompt profile 与历史上下文。
- K3 不再错误继承 Anthropic-native 的 `forceAdaptiveThinking` / `allowEmptySignature` 配置。
- Kimi K2.7 继续保留 `supportsStrictMode=false` 与 DeepSeek thinking 格式，不因 K3 修复产生工具或思考回归。
- 修复前的真实错误为 `400 role 'developer' is not allowed`；修复后 VSPLab K3 完整请求使用 `system` instruction。

## Provider 配置收敛

- 当前 VSPi 安装统一使用 `vsplab` Provider 与 `https://api.vsplab.cn/v1` API root。
- 遗留 `vsplab-open` 与 `vsplab` 使用相同 credential，已从本机模型目录、认证记录和默认 Provider 中移除；历史 Session 文件保持不变。
- Pi 与 VSPi 默认模型统一为 `vsplab/k3`，避免非交互执行和 TUI 选择不同 Provider。

## CI 与验证

- GitLab tag pipeline 新增 `quality` stage，在打包和发布前执行 TypeScript/Biome 检查与完整测试。
- GitHub Release workflow 同样在构建 release assets 前运行 `npm run check` 和 `npm test`。
- 完整验证覆盖 147 个测试文件、1098 个测试、Provider catalog、request payload normalization、PTY、多进程 Session handoff 与 npm package install。

## 安装

已有 VSPi 可运行：

```text
vspi update
```

或手动安装：

```powershell
npm install --global "https://gitlab.vsplab.cn/heyx/vspi/-/releases/permalink/latest/downloads/vspi-latest.tgz"
vspi --version
```
