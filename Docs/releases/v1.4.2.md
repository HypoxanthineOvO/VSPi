# VSPi 1.4.2

VSPi 1.4.2 修复 Cron 工具在部分 Provider/模型组合下生成空参数的问题，补齐临时网关错误的有界自动重试反馈，并完善模型价格名称解析。

## Cron 工具兼容

- `CronCreate` 不再向 Provider 暴露顶层 `anyOf` union，改为普通 object schema，提升 `openai-responses` 等工具调用链对参数生成的兼容性。
- VSPi 执行层继续强制 `cron`、`after`、`run_at` 必须恰好提供一个；one-shot 不接受 `recurring`，没有放松调度约束。
- 新增 Provider 可见 schema 回归测试，明确禁止 `CronCreate` 顶层重新出现 `anyOf` / `oneOf`。
- 增加真实 `CronCreate -> CronList -> CronDelete` 冒烟验证，并覆盖相对 one-shot、空 schedule、冲突 schedule 与模式专属参数。

## Provider 临时错误重试

- 对 `stream_read_error` 和网关 `upstream_error: Upstream request failed` 补充可重试的 503 语义，使 Pi 的有界重试分类器能够识别临时故障。
- 非临时错误、用户取消与请求参数错误保持原样，不会被扩大为自动重试。
- 自动重试期间 Session 保持 busy；TUI 显示重试次数、等待时间以及最终恢复或失败结果。

## 模型价格解析

- 新增规范化完整模型名解析，兼容大小写、空格和下划线差异；已知价格档可按 `GPT-5.6 Sol / Terra / Luna`、`GLM-5.2` 等完整型号命中。
- 补充 GPT-5.6 Terra catalog estimate：输入 $2、输出 $12、cache read $0.2、cache write $2.5 / 百万 tokens，按 USD/CNY 6.80 记录为人民币估算档。
- 名称推断只匹配已有完整型号，不按相邻版本或前缀猜价。Pi catalog 当前没有 GLM-5.3 的可靠非零价格，因此 GLM-5.3 继续显示 unknown，不套用 GLM-5.2。
- `officialCny`、`catalogEstimateCny` 与 `providerBilledCny` 继续分离；catalog estimate 不冒充 Provider 实际账单。

## 验证

- TypeScript 与 Biome 检查通过。
- 覆盖 Cron schema/执行、Provider 请求兼容、自动重试状态、价格解析、缓存费用和 usage telemetry。
- 完整生产构建、Vitest、PTY、多进程 Session handoff 与 npm package install 测试通过。

## 安装

已有可工作的 VSPi 可运行：

```text
vspi update
```

或手动安装：

```powershell
npm install --global "https://gitlab.vsplab.cn/heyx/vspi/-/releases/permalink/latest/downloads/vspi-latest.tgz"
vspi --version
```
