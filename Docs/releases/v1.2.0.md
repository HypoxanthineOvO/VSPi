# VSPi 1.2.0

VSPi 1.2.0 新增 `vspi exec` 非交互执行入口（支持续接会话），并修复 Goal 面板输入黑洞与 `/` 前缀冲突两个高频反馈问题。

## 非交互执行：vspi exec

- `vspi exec "<prompt>"`：新会话执行单个 prompt，最终 assistant 文本输出到 stdout，运行期 notice 输出到 stderr。
- `vspi exec resume "<prompt>"`：续接最近会话执行；`vspi exec resume <session-id> "<prompt>"` 续接指定会话，session id 支持唯一前缀（可在 TUI 的 `/sessions` 面板查看）。
- `vspi run "<prompt>"` 保留为兼容别名，行为与 `exec` 一致。
- 退出码：0 成功、1 运行失败、2 用法错误、130 已取消；用法错误不再以未捕获异常崩溃。
- `--policy`、`--trust-project`、`--recovery`、`--workflow` 可出现在 exec 参数任意位置；被其他 VSPi 进程持有的会话通过既有的前台移交机制等待接管。

## Goal / Prompt 面板输入黑洞修复

- 输入 `/goal` 直接回车会打开 Goal 状态面板，但该面板此前没有任何按键注册，打字、Enter、Esc 全部被静默吞掉，表现为"输入 /goal 没有内容就卡死"。Goal 与 Prompt 面板现在都注册了 Esc 关闭，面板会宣告退出方式；Prompt 面板 import 路径编辑态下 Esc 只取消编辑、不关闭面板。
- 交互 Registry 新增契约：所有模态面板必须注册 Esc 关闭，防止同类回归。

## 命令输入路径修复

- 命令面板只拦截无参数 slash token 的 Enter：带参数输入（如 `/goal status`、`/compact custom 说明`）一律由 composer 完整提交，参数不再被面板激活路径丢弃。
- 以 `/` 开头但未匹配命令的内容（如路径 `/home/user/project`）不再报"未知命令"，直接作为普通消息发送。
- 新增 `//` 转义：`//goal hello` 字面发送 `/goal hello`，输入过程中不弹命令面板。

## 验证

- 全量 Vitest 通过（133 个文件、994 个用例），含真实 PTY、Session continuity、package install 与 release surface。
- `npm run check`（tsc + biome）通过。
- fixture 后端下 `vspi exec` / `vspi exec resume` / `vspi exec resume <id>` / `vspi run` CLI 冒烟验证通过。

## 安装

已有可工作的 VSPi 可运行：

```text
vspi update
```

或手动安装：

```powershell
npm install --global "https://gitlab.vsplab.cn/heyx/vspi/-/releases/permalink/latest/downloads/vspi-latest.tgz"
vspi --version
```
