# VSPi 1.3.2

VSPi 1.3.2 让 Provider/model 已变化的历史 Session 可以自动恢复，并为同主机无响应 Session owner 提供显式、安全的终止接管流程。

## Session 模型 fallback

- 历史 Session 记录的模型不可用时，不再因为 Pi 已解析 fallback 而拒绝打开。
- 原 Provider 仍有可用模型时优先选择该 Provider 的首个可用模型；原 Provider 已删除或无认证时，使用当前全局默认或 Pi 已解析的其他可用模型。
- 自动选择通过标准 `session.setModel()` 写入 `model_change`，下次打开不再重复 fallback，并显示一次非阻塞提示。
- VSPi runtime default 不会覆盖刚完成的同 Provider fallback；默认 Effort 仍正常应用。
- 完全没有可用 Provider/model、fallback 为占位模型或持久化失败时继续 fail closed。

## 无响应 owner 恢复

- 正常 Session handoff 保持不变：旧 runtime 完成 generation、工具和队列后原子移交，不会因任务耗时而被中断。
- 接管握手前无响应，或已接受接管但 heartbeat 停止 15 秒时，新 TUI 显示显式恢复确认。
- 恢复先发送 SIGTERM；3 秒后仍未退出时再次确认才发送 SIGKILL。只有验证原进程实例已经退出后才删除旧 lease 并接管。
- Linux lease schema v2 记录 boot ID、进程 start time 与 UID，防止 PID reuse 时误杀无关进程；recovery claim 串行并发恢复者。
- 旧 schema、跨主机、不同 UID、非 Linux 或不可验证进程身份时拒绝强制恢复，可继续等待或创建分支。

## 贡献

- 本次 Session 模型恢复基于李超凡在 MR !4 中提交的 fallback 检测、持久化和生命周期测试，并按最终产品语义改为无阻塞自动 fallback。

## 验证

- 全量 Vitest 通过（136 个文件、1027 个用例），并通过 TypeScript、Biome、构建、CLI smoke 和发布 tarball 安装验证。
- 覆盖 Provider 删除、同 Provider fallback、正常多进程 handoff、握手超时、accepted 后冻结、PID reuse、recovery claim 与 TERM/KILL UI。

## 安装

已有可工作的 VSPi 可运行：

```text
vspi update
```

或手动安装：

```powershell
npm install --global "https://gitlab.vsplab.cn/heyx/vspi/-/releases/permalink/latest/downloads/vspi-latest.tgz"
vspi --version
```
