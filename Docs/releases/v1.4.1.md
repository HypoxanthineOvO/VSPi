# VSPi 1.4.1

VSPi 1.4.1 用 Kimi Code 的 durable task/subagent lifecycle 替换 1.4.0 中仍依赖内存 map 与 floating Promise 的执行路径。VSPi 保留自己的 Pi AgentSession、Provider/model 路由、Policy、workspace 安全边界和运行时间限制。

## Durable Agent Task Runtime

- 前台与后台 Subagent 统一注册为 task，状态为 `running / completed / failed / timed_out / killed / lost`。
- task metadata 与完整 output log 分开原子持久化；实时 assistant delta 进入 output log，默认 16 MiB 上限，超限停止任务。
- `TaskList`、`TaskOutput`、`TaskStop`、`WaitFor` 同时提供给主模型和 child；output 支持 bounded preview 与 offset 分页。
- `WaitFor` 可以等待指定 task，或等待调用时已经运行的任一 task；它不发模型请求、不停止任务，且已交付的 terminal 结果不会重复触发 automatic notification。
- 前台 task 可通过 `/agents detach <task-id>` 转入后台；`/agents stop <task-id>` 明确停止。

## Completion Outbox 与恢复

- completion notification 先持久化为 `pending`；主 Session 忙、注入失败或进程在投递边界退出时不会静默丢失。
- 主 Session idle、runtime 重建和启动恢复会重试 pending notification；投递前检查 transcript 中相同 `taskId`，避免重复注入。
- 异常退出留下的 running task 在新进程恢复为 `lost`，保留 metadata 与 output，不伪造继续运行。
- Session 正常关闭产生 `killed`，并抑制关闭过程中的无意义自动通知。
- compaction 后向模型列出仍在运行的 durable task，提示使用 Task tools，避免重复启动。

## 持久 Child 与 Resume/Fork

- 每个 child 使用独立持久 Pi Session，而不是 `SessionManager.inMemory`。
- task metadata 保存 child session binding；VSPi 进程重启后可以用稳定 `agent_id` resume 已完成 child。
- 同一主 Session 的 Pi runtime 因模型切换或重建时复用 AgentManager，不会把仍在运行的 task 误标为 `lost`。
- `fork=true` 创建新 child，并将 caller 已完成 conversation 作为一次性 reference snapshot；fork 不与 resume、model/type override 混用。

## Kimi Source Mapping

移植基于 `MoonshotAI/kimi-code` commit `676e4d82240855044fe809fea89ce1dbe8e512cf`：

- `agent/task/taskService.ts`、`persist.ts`、`types.ts`：状态、持久化、output、stop/wait、lost reconciliation、notification delivery。
- `agent/tools/agent/agentTool.ts`、`subagent-task.ts`：foreground/background、detach、resume、fork 与 task registration。
- `session/subagent/runAgentTurn.ts`、`mirrorAgentRun.ts`：summary 保留、terminal classification 与 lifecycle projection。
- TUI task browser/activity store：active-first 列表、terminal state 与 bounded activity detail。

Kimi 的 DI Scope、Kosong model engine、Provider catalog 和 XState Session 架构没有引入；这些由 VSPi 的 Pi runtime 适配层承担。

## 验证

- 新增真实子进程 `SIGKILL` 恢复测试，验证 running task 变为 `lost` 且 output 保留。
- 新增 100 task 并发 soak，验证 metadata、terminal 状态和 per-task output 顺序。
- 覆盖 notification retry/去重、WaitFor exactly-once、output cap、foreground detach、同 Session runtime rebind、跨 manager resume、fork、compaction reminder、Recovery 和 Session handoff。
- 全量 TypeScript、Biome、生产构建、PTY、多进程和 package install 测试通过。
