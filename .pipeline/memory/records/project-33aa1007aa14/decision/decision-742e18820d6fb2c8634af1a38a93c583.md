# Release history authority and reconstruction policy

Use the peeled Git tag commit on main as the authoritative release anchor for v0.2.0 through v0.3.11. Treat commit c0f5829b91dc1a95e79962013a76135c37d278b0 as the explicit v0.1.0 release baseline because package.json and the commit message set 0.1.0 but no v0.1.0 tag exists.

Preserve existing accepted Hypo-Workflow Delivery objects as the authority for planned Cycle or Goal history. A Git release may be linked to an accepted Delivery when timing, scope, and Session evidence agree, but reconstruction must not fabricate a historical Cycle, Goal, Receipt, or acceptance. Releases without a matching Delivery are recorded as direct iteration backed by Git and the main user Session, while subagent Session branches remain supporting evidence rather than independent project requirements.
