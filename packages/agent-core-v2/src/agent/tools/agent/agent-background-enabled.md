Subagents run in the background by default when `run_in_background` is omitted. The tool returns immediately, and completion arrives in a later turn as a synthetic user-role message containing the result — do not poll, sleep, check progress, or call WaitFor. Continue with independent work if any; if a background subagent is already running and no independent work remains, end the current turn and let the automatic notification resume the work. Never fabricate or predict what the result will say.

Set `run_in_background=false` when you must obtain the result synchronously from the outset; foreground execution waits and returns the result directly. Never launch in the background and then wait on it.
