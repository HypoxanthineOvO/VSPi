# 会话与对话

## 现在

- VSPi 的会话在 daemon 里运行。退出终端前端不会取消正在运行的任务，之后可以续接会话。
- 启动时可新建会话、继续最近的会话，或用 `/sessions` 选择历史会话。会话按工作区分组列出，并显示标题、状态和归档标记。
- 支持从现有会话 fork 新会话；fork 后使用新的会话标识，原会话保留。
- 支持旁路问答：`/btw`（别名 `/side`）继承当前上下文，只使用 Read、Grep、Glob 查阅文件，主任务继续运行；可连续追问，`Ctrl+C` 取消回复，Esc 关闭。
- 支持运行中插话（Steer）：输入先进入等待区，真正写入上下文并开始对应模型调用时才显示为已送达。
- 子 Agent 有独立的对话流，实时状态显示在 Agents 区域和 `/agents`；后台任务和进程状态显示在 `/tasks`。
- 转写按时间顺序展示用户消息、助手消息、思考、工具调用、子 Agent、用量和模型切换。工具或任务更新时改原节点，不把节点移到末尾。
- 常规模式下，已经滚出视口的行进入终端原生滚动区，不再改写；窗口尺寸稳定后，新输出接在底部，历史仍可上滚查看。全屏模式由 `/tui` 切换。

## 规则

- 退出前端不取消后台任务；daemon 结束时才结束会话进程。
- 会话恢复以 daemon 保存的会话状态为准。恢复已有会话时，不重新应用草稿里的权限选择。
- 父 Agent 和子 Agent 的内容分区展示：子 Agent 的实时过程不进主转写。
- 常规模式不重放已经输出的历史，也不清空原生滚动区。
- 模型切换分隔线只属于当前 TUI 展示，重新加载历史时不恢复。

## 不能坏

- 转写必须保持时间顺序，更新工具或任务时不能改变节点位置。
- 常规模式不能发送 `ESC[2J`，不能清空原生滚动区。
- 每帧最多处理 200 行，超出部分排队，不能丢消息。
- 输入框非空时，中断操作不能丢掉用户已经输入的文本。
- 子 Agent 的 `/agents` 视图不能显示思考内容，也不能把子对话混进主转写。

## 牵连

- daemon 与 IPC：会话创建、恢复、fork 和事件流都经过 daemon。
- 模型选择：会话保存自己的模型和 Effort，恢复时沿用。
- Provider 管理：缺少可用 Provider 时会话无法发起模型请求。
