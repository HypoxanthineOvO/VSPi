# 会话与对话

## 现在

- VSPi 的会话在 daemon 里运行。退出终端前端不会取消正在运行的任务，之后可以续接会话。
- `vspi resume` 和 `/sessions` 按 `Tab` 切换 Current workspace / All，范围偏好全局保存；All 平铺当前 VSPi home 内所有工作区的未归档会话，按最近活动时间倒序。显示标题、目录和时间，支持标题/目录搜索及向下加载后续页；搜索会扫描后续页，不限前 100 条。
- `Enter` 恢复会话，`Ctrl+F` 创建分支，`Esc` 先清空搜索、再退出。恢复跨目录会话后，界面目录、文件补全、图片路径和新会话目录同步为目标目录。
- 支持从现有会话 fork 新会话；fork 后使用新的会话标识，原会话保留。
- 支持旁路问答：`/btw`（别名 `/side`）继承当前上下文，只使用 Read、Grep、Glob 查阅文件，主任务继续运行；可连续追问，`Ctrl+C` 取消回复，Esc 关闭。
- 支持运行中插话（Steer）：输入先进入等待区，真正写入上下文并开始对应模型调用时才显示为已送达。
- 子 Agent 有独立的对话流，实时状态显示在 Agents 区域和 `/agents`；后台任务和进程状态显示在 `/tasks`。
- 新会话内置六个叶子角色：explore 查代码/调用链，coder 做后端/打包/通用实现/批量修改，frontend 做前端/视觉/视频，plan 是默认技术规划角色，reviewer 审行为变化和缺陷，consultant 仅用于用户意图分歧、重要产品取舍或用户点名。所有角色不再派子 Agent，最后一条自然语言消息作为交接，不自动接力 reviewer。
- 用户一次性在现有 `config.toml` 的 `[role_routing.<角色>]` 保存 default 与可选档位 alias；CLI section 是 `roleRouting`。coder 使用 fast/default/hard，frontend 额外支持 mid/high；机械活 fast，常规实现 default，困难功能 hard，中等视觉 mid，高要求视觉/视频 high。映射表由主提示词生成，非默认档位通过既有 Agent/AgentSwarm `model` 参数传实际 alias，不增加 schema 字段。
- 角色 default 只影响非 fork、非 force、没有显式 model 的新建任务，最终通过现有子模型池校验；配置错误明确报错，不静默换模型。fork/resume 保持原绑定；未配置角色继续用原有池默认/继承。`roleRouting = {}` 可停用路由，仍保留六角色；用户和项目角色仍可按现有优先级覆盖产品预设。目录和主方路由说明以新会话为准，default 每次新建时重新读取。
- plan/consultant 不开放 shell/写工具；explore/reviewer 不开放写工具，为只读 git 保留 Bash，提示词限定 log/blame/show/diff/status、禁止脚本/构建/写入和外部 diff/textconv。Bash 只读是提示词约束，不是命令级隔离。
- 转写按时间顺序展示用户消息、助手消息、思考、工具调用、子 Agent、用量和模型切换。工具或任务更新时改原节点，不把节点移到末尾。
- 常规模式下，已经滚出视口的行进入终端原生滚动区，不再改写；窗口尺寸稳定后，新输出接在底部，历史仍可上滚查看。全屏模式由 `/tui` 切换。

## 规则

- 退出前端不取消后台任务；daemon 结束时才结束会话进程。
- 会话恢复以 daemon 保存的会话状态为准。恢复已有会话时，不重新应用草稿里的权限选择。
- 父 Agent 和子 Agent 的内容分区展示：子 Agent 的实时过程不进主转写。
- 常规模式不重放已经输出的历史，也不清空原生滚动区。
- 模型切换分隔线只属于当前 TUI 展示，重新加载历史时不恢复。

## 不能坏

- 转写必须保持时间顺序，更新工具或任务时不能改变节点位置。
- 常规模式不能发送 `ESC[2J` / `ESC[3J`，不能清空原生滚动区。刷新重建用 CPR（光标位置查询）定位并原地擦除旧 dock，正文不擦除、不重放，新 dock 锚定屏幕底部。VS Code 等白名单终端缩窄时共用通用重排公式，结合旧帧行宽和光标列保守计算擦除起点，旧输入框上边框可能残留在终端历史中。等待查询时暂停帧输出；200ms 无响应则不擦除，退回保守上滚。`VSPI_TUI_REFLOW=1/0` 强制开启或关闭缩窄时的折行回退模型，默认按终端白名单识别；未识别终端只回退旧逻辑行数。
- 每帧最多处理 200 行，超出部分排队，不能丢消息。
- 输入框非空时，中断操作不能丢掉用户已经输入的文本。
- 子 Agent 的 `/agents` 视图不能显示思考内容，也不能把子对话混进主转写。

## 牵连

- daemon 与 IPC：会话创建、恢复、fork 和事件流都经过 daemon。
- 模型选择：会话保存自己的模型和 Effort，恢复时沿用。
- Provider 管理：缺少可用 Provider 时会话无法发起模型请求。

## 未定

- 会话标题是否需要支持手动重命名。
- 长时间运行的子 Agent 是否需要在主转写保留一条可展开的摘要。
- VS Code 等终端缩窄时，旧输入框的上边框会残留在终端历史里，典型单次缩窄约 2 行，多次缩窄累加。终端历史是否已满不可知，为保证不擦正文而保守处理；如何进一步减少残留未定。
