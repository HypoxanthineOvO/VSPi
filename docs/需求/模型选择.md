# 模型选择

## 现在

`/model` 和 `vspi config` 里的默认模型选择共用同一套模型展示。

- 模型按公司分组；同一模型在多个 Provider 上有来源时，只在模型行展示一次，展开后列出各个来源。
- 每个来源显示品牌、健康状态、价格和上下文；默认来源用实心圆点标记。
- 来源排序先排除最近失败的来源，再优先手动记住的来源，最后按 Provider 优先级。
- 所有来源都失败时，不自动选一个来源，要求用户展开并确认具体来源；再次按 Enter 才使用，不会自动切换。
- 健康记录来自真实模型请求：区分凭据被拒绝、模型不存在、限流、网络异常和其他失败；不同类别有不同的有效期。这里不做额外计费探测。
- 置顶和最近使用保存在 `~/.config/vspi/model-picks.json`；打开选择器时焦点落在当前模型。`Ctrl+P` 置顶或取消置顶，`Ctrl+O` 在常用和全部之间切换。
- 搜索覆盖当前视图中的模型名称、ID、别名、公司和 `@Provider`；`Ctrl+O` 切换全部模型后可搜索完整目录。
- 规范身份可在 `[models."Provider/模型".canonical]` 手动覆盖 `id`、`company` 和 `display_name`；默认来源顺序可在 `[model_catalog] provider_priority` 设置，不能改变实际请求模型 ID。
- 选中模型后先暂存，确认 Effort 才生效；Esc 不改变当前绑定。选择器不显示 Off。
- Devin 的思考档位和上下文变体会归并到同一个模型组，来源与档位分别展示。

## 规则

- 各来源相互独立，不用一个来源的失败去推断另一个来源。
- 健康只反映最近一次真实请求，过期记录显示为“记录已过期”，不继续当成失败。
- 用户手动选择的来源优先于 Provider 默认优先级；没有手动记录时才按优先级选择。
- 当前绑定在确认 Effort 之前保持不变。

## 不能坏

- 不能自动把请求切到另一个来源。
- 不能把累计用量显示成当前上下文。
- 恢复已有会话时，不能用全局默认模型覆盖会话自己的选择。
- 主模型的常用星标不能用来生成子 Agent 候选池。

## 牵连

- Provider 管理：新增、删除或编辑 Provider 会改变可选来源。
- Devin 登录与模型：Devin 模型组和来源健康进入同一套排序。
- Effort：模型确认后才进入档位选择，档位按模型别名保存。
- 会话：恢复会话时沿用会话已保存的模型和 Effort。
