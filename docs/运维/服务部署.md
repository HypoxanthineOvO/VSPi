# 服务部署

## 现在

VSPi 的发行包、反馈接收和模型目录维护走三条独立的部署路径。

**发行包**：在 Linux 工作机本地构建、验证和打包，再用 `scripts/github-release-producer.mjs` 创建 GitHub Release。GitHub Actions 不负责构建或验收。发布步骤和产物校验见 `apps/vspi/docs/development.md`。

**反馈接收与公网转发**：维护者用 `scripts/prepare-vspi-admin.mjs` 生成管理员操作包，交给管理员执行。

- `ops/vspi-services/eden-admin.sh` 在 Eden 安装反馈接收服务，创建专用服务用户，保留现有 Nginx 站点，最后由管理员显式激活。
- `ops/vspi-services/hypo-admin.sh` 在公网转发机向现有 Caddyfile 增加受控转发，不启用磁盘缓存或整包缓冲。
- 两个脚本都先跑 `preflight`，再按 `install`、`activate` 的顺序执行。
- 反馈正文保存在 Eden；公网节点只转发。发布签名和反馈接收是两个独立授权步骤。

**模型目录**：`ops/vsplab/model-catalog.json` 是 VSPLab 中转站 `/vsp/models` 的权威内容。修改后同步到中转站：

```sh
scp ops/vsplab/model-catalog.json <relay-host>:/etc/vsp-sub2api/model-catalog.json
```

2.5.1 起该目录也随客户端发布内置于默认值，用户差异写在 VSPi home 的 `config.toml`，服务端目录不会覆盖新版客户端的用户配置。

## 规则

- 域名、证书、防火墙和定时任务由管理员另行配置和核实，操作包不自动改。
- 密码、私钥、token 和签名密钥不进仓库，也不在聊天或日志里粘贴。
- 服务器地址和主机名在文档里用占位符，实际值由管理员从可信渠道核对。
- 发布签名密钥保存在离线或 root 专用位置，常规服务账号不能读取。
- 反馈接收服务使用单进程锁和受限的文件权限，不能把配置组权限授给只读账号。

## 测试

- 生成管理员操作包后，先在两台目标机执行 `preflight`。
- 安装后在目标机确认服务状态、端口只监听本机或受控地址、反向代理能通过证书校验。
- 模型目录同步后，从客户端读取 `/vsp/models`，确认返回内容和维护源一致。
